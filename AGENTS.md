## Start and verify

Serve the root over HTTP (service workers and module-like browser behavior should not be tested with `file://`):

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

Open `http://127.0.0.1:8765/`. There is no dependency install or app build. Run the focused update regression checks with `node --test test/updates.test.mjs`. Minimum static checks after changes:

```bash
for file in js/*.js service-worker.js; do node --check "$file"; done
python3 -m json.tool manifest.json >/dev/null
python3 -m json.tool manifest.webmanifest >/dev/null
node tools/release.mjs --check
```

Also confirm every `service-worker.js` shell asset exists, HTML IDs remain unique, all static `getElementById`/`$(...)` targets still exist, and test desktop plus phone Touch UI manually. For cloud changes, test signed-out local use, OAuth return, clean sync, dirty sync, offline edit/reconnect, second-browser restore, deletion propagation, and disconnect.

- `js/app.js`: core form/logger UI, autosave, keyboard/touch controls, primary-view lifecycle, theme/rain/scale, JSON backup/restore, and a save-queue flush that can block update reloads on save failure.

## Data and behavior

IndexedDB is the immediate source of truth. Database `ThunderShadowBrowserDB`, schema version 1, stores:

- `forms`: metadata plus embedded `entries`/compatibility alias `questions`.
- `rules`: saved canonical rules, aliases, review history, status, notes, and source pointers.
- `settings`: synced desktop `ui_scale` and the four review intervals (`again`, `hard`, `good`, and `easy`, in days), plus configurable `review_shortcuts`.
- `backups`: verified full JSON snapshots (14 retained; scheduled at most every 24 hours during idle time).
- `meta`: tombstones and backup timestamps.

Entries have an optional `examItem` (simulator `block.item`, normalized by `ThunderShadowReasoning.normalizeExamItem`: `3.1`→`3.01`, blank allowed, invalid rejected; set via the Error code header box `#examItemInput` with paste button `#examItemPasteBtn`, clipboard read with focus/select fallback). It persists through `normalizeEntry`, edits, backups and Drive sync with no migration (old entries are `""`), and is exported as the LAST column `Exam_Item` of the per-form and combined log TSV (ThunderNBME joins on it by header; never reorder/rename earlier columns). Entries have stable monotonic `entryNumber`, error code 1-7, one canonical reasoning pattern, zero or more speed flags, study note (`reasoningNote` / compatibility alias `manualRule`), `noteKind` (`clinical` or `reasoning`), deterministic `noteId` (`<form-id>:entry-<number>`), soft-delete state, revision, and timestamps. Forms and entries are normalized defensively for old backup/Drive shapes. Optional entry ruleId/ruleSyncIdentity/ruleSyncText fields bind an authored note to its canonical card and distinguish subsequent wording/tag edits from independent library edits. ThunderShadowID is always derived as `thundershadow:<rule-id>`; existing saved IDs/Anki IDs are preserved. New cards use a deterministic `log:<encoded-form-id>:entry-<number>` rule ID, exact duplicates reuse existing canonical rules, and log/source IDs remain distinct from card IDs. Permanent form/rule/entry deletions create timestamped tombstones so another device cannot resurrect them.

Storage resilience is deliberate: IndexedDB opens time out after 3.5 seconds and transactions after 6.5 seconds; failure switches to a new recovery database without deleting the original. If recovery also fails, `localStorage` emergency stores keep forms/rules/settings/meta working. Full browser snapshots are disabled in emergency mode to avoid quota exhaustion. Recovery clears the cloud dirty ledger and cached Drive index so an empty fallback store cannot be uploaded as authoritative deletion.

Device-only `localStorage` preferences include theme, desktop/touch UI, rain on/off, phone section expansion, review text size (`thundershadow:review-text-size`), drafts, lightweight form cache, recovery markers, and cloud/session metadata. Desktop scale, review intervals, and review shortcuts are included in synced settings. Do not put OAuth/session values in exports, backups, logs, or Drive objects.

Core browser-API families: forms and entries CRUD/restore/permanent delete/TSV; JSON backup and destructive restore; browser snapshots/list/preview/download/restore; encrypted `.tsbackup` export/import preview; analytics; rules/merge/review/selected-review/suspend/delete; longitudinal TSV, active-rules TSV, Anki TSV, analytics JSON, ChatGPT-analysis Markdown; settings. Restore is intentionally destructive after validation and creates a safety snapshot first. Portable archives use PBKDF2-SHA-256 (240,000 iterations) plus AES-256-GCM; passphrases are never stored.

UI guarantees: desktop scale 80-120%; explicit Desktop/Touch modes; light/dark/system themes; device-local rain toggle (Off stops rain, cloud drift, and lightning while retaining the static backdrop; reduced motion also stops all storm animations; hidden pages stop enabled storm animations and release their animated surfaces); phone uses `visualViewport`, safe areas, one renderable primary view, an internal logger scroll surface, persistent optional-section preferences, and phone-native analysis tables. ## Cloud contract and invariants

Cloud is optional; local saves must never wait for or depend on it.

- Config: app ID `thundershadow`; Worker `https://study-tools-auth-worker.summerofdawn20.workers.dev`; scope `https://www.googleapis.com/auth/drive.appdata`.
- Connect redirects to Worker `/oauth/start` with `app_id`, `return_url`, and persistent device ID. Callback `#cloud-auth=<Worker session>` is stored as `cloudflareWorkerSession` and stripped from the URL immediately.
- Worker `/token` exchanges that session for a short-lived Google access token kept only in memory. `/disconnect` clears the Worker/local session but does not delete local data or Drive files. Google refresh tokens/client secrets remain server-side.
- Drive namespace: `thundershadow-manifest.json`, one `thundershadow-form-<base64url-id>.json` per form, one rule file per rule, and `thundershadow-settings.json`. The manifest carries hashes, schema metadata, device marker, and tombstones.
- Durable local mutations first persist a dirty ledger at `thundershadow:cloud-dirty-state`, then emit `thundershadow-local-data-changed`. Normal sync debounce is 7.5 seconds; destructive/finish/restore events request immediate sync.
- Startup silently refreshes and syncs; clean foreground checks are throttled to 60 seconds; reconnect flushes dirty state. Token/Drive requests time out after 15/20 seconds. First restore reads at concurrency 4.
- Clean sync uses Drive file metadata as a fast path. Hashes skip unchanged writes. One dirty entry updates its containing form file plus manifest.
- Remote data is merged incrementally into live IndexedDB, never via full-store replacement. Page-local API operations and remote merges are serialized; ordinary note reconciliation reads only the changed form plus rules. Derived rule/link reconciliation after remote merge or confirmed restore is silent, preserves tombstones, and emits no cloud echo. Local rule/link writes persist their dirty IDs immediately. If derivative rule storage fails, authored notes still save and mark their forms dirty, a warning is shown, and a later API access retries reconciliation. Forms/entries resolve by timestamps then revisions; rules union aliases/reviews; tombstones win over older records. Remote application emits no local mutation event, preventing an echo loop.

Never weaken these invariants: local-first operation, non-destructive cloud merge, tombstone propagation, no secrets in frontend/data files, no cloud activity in the service worker, and no wholesale database clearing except an explicitly confirmed restore.
